# 15 — Build Plan

Sequenced so the riskiest assumption is tested first and the product is demonstrably useful
before any AI is written. **The SCD suite proves the concept; the agents make it scale.**

## Milestone map

```
M0 Foundations ─▶ M1 Engine ─▶ M2 SCD suite ─▶ M2B Layer parity ─▶ M3 Lane A live ─▶ M4 Reporting agent
                                    │             (L2 dedup, L3)        │                    │
                                    └─────────────────▶ M5 Lane B / L1 ─┴────────────────────┴─▶ M6 Authoring agent
                                                                                                     │
                                                                                               M7 Shadow → go-live
```

---

## M0 — Foundations

**Goal:** the tool can connect, validate config, and write state. Nothing checks anything yet.

- `pyproject.toml`, Docker image, ruff / mypy --strict / import-linter in CI.
- `config/` models and loader, including the secret-literal scan.
- `api/` skeleton: FastAPI, OIDC login, RBAC dependencies, the diagnostics endpoint.
- `web/` skeleton: Vite + React, generated API client, a Settings screen showing diagnostics.
- `catalog/` readers for both engines.
- `state/ddl.sql`, `migrate.py`, `repo.py`, `permissions.py`.
- `api/routes/diagnostics.py` — the connection/grant/migration health checks.

**Exit criteria**
- Signing in with SSO and opening Settings shows every connection healthy — RDS, Snowflake roles
  and grants, state migration level, git, LLM — or a precise error.
- `DPHM_STATE` exists; a permission fingerprint is recorded.
- CI green, import rules enforced (no `langchain` outside `agents/`).

**Blocked by:** A1 (roles), A3 (repo access). Confirm before starting — see `16`.

## M1 — Check engine

**Goal:** a hand-written check runs, and reports honestly what it compared.

- `engine/dialect/`, `render.py`, `columns.py`, `scope.py`, `execute.py`, `result.py`.
- Templates: `keys/grain_unique`, `keys/key_not_null`.
- SQL snapshot test harness.
- `runtime/` job table, worker pool, and the advisory lock.
- `POST /projects/{p}/runs` plus a minimal Runs screen — **a thin vertical slice of the app from
  M1 onward**, so the UI is never a big-bang at the end (see `02` D4).

**Exit criteria**
- A grain-uniqueness check runs on a real table and writes a result row.
- The result carries non-empty `COLUMNS_COMPARED` / `COLUMNS_EXCLUDED` / `SCOPE_PREDICATE`.
- Batch scoping resolves from the real control table; an unresolvable scope yields
  `INCONCLUSIVE`, not a guess.

**Risk retired:** R1 (audit columns) and R2 (mid-load reads) are structurally handled from here on.

---

## M2 — The SCD suite and the four gates

**The most important milestone. Everything after it is amplification.**

- All 11 SCD templates.
- The mutation injector catalogue and runner.
- All four gates, wired into `check validate` / `check activate`.
- The Checks screen with gate badges, and the Coverage screen.

**Exit criteria**
- 11 checks generated by hand for one real migrated dimension, all four gates green.
- **Injector 7 fails check 7**: a tracked column updated in place on the current row, with no new
  version, is caught. This is the product's core claim, demonstrated.
- The Coverage screen shows checked vs. unchecked objects and unconfirmed grains, and the
  Activate button is disabled with a gate-naming tooltip on any check that failed a gate.
- Every template has a catalogue entry; CI enforces it.

**Demo:** run the suite on the real dimension, then run it again against a clone with injector 7
applied. This is the demo that earns the rest of the roadmap.

---

## M2B — Layer parity: bronze → silver → gold

**Goal:** every same-engine hop of the medallion is checked, anchored on the dedup contract.

- `config/` support for `layers.yaml`; `engine/hops.py` (`HOP_CHECK_BUNDLES`) and
  `engine/layer_graph.py`.
- L2 templates: `dedup_key_unique`, `dedup_pick_rule_fidelity`, `dedup_pick_rule_total`,
  `row_conservation`, `no_invented_keys`, `no_lost_keys`, `reject_reasons_closed`.
- L3 templates: `dim_key_coverage`, `dim_matches_silver`, `measure_conservation`,
  `fk_resolves_as_of`, `group_cardinality`, `aggregate_of`.
- `repo/dedup_extract.py` — read the dedup key and pick rule out of `QUALIFY` / `ROW_NUMBER` /
  `DISTINCT ON` in the transform SQL.
- Mutation injectors for every layer template.

**Exit criteria**
- The L2 dedup contract for one real bronze→silver hop is written by hand into `layers.yaml`,
  human-confirmed, and all nine L2 checks pass on real data.
- **Injector L2.5 fails the pick-rule check**: replacing the surviving row with a different
  duplicate of the same key is caught — while row counts, key sets, and conservation all stay
  green. This proves the hop's contract is doing work no counting check could do.
- **Injector L2.6 fails the totality check**: a bronze row duplicated to tie on the full ordering
  is caught, and reported as an under-specified contract rather than as bad data.
- L3 recomputes one mart from silver and names a seeded one-unit measure difference.
- L3 reports the mart's non-additive measures as unverified, in the coverage output.
- A seeded L2 failure **suppresses** the downstream L3 incident, and one incident is filed at L2.

**Why here:** the dedup contract is the pipeline's most consequential undocumented assumption, and
it is cheap to check. Doing it before any AI means the layer contracts we later ask an agent to
infer are ones we have already written by hand and understand.

## M3 — Lane A live, deterministic reporting

**Goal:** scheduled runs with real, deduplicated alerts. No AI yet.

- `state/incidents.py` (fingerprinting, lifecycle), `state/signoff.py`.
- `reporting/slack.py` with Block Kit and the four buttons; `reporting/jira.py`.
- `evidence/` collectors: schema diff, load history, git history, prior incidents, audit columns.
- Shadow mode.
- The app's Overview, Pipeline (medallion), and Incident screens — including the
  **non-collapsible "what we are not checking" panel**.
- The scheduler and the signed `/hooks/load-complete` webhook.

**Exit criteria**
- A seeded failure produces one Slack message in the shadow channel with evidence, compared and
  excluded columns, and the scope predicate.
- The same failure next run **updates the thread**, no second message, no second ticket.
- A different failing row creates a new incident.
- A sign-off bound to a commit expires when the watched file changes.
- Slack buttons write `FEEDBACK`.

**At this point the product is useful without any LLM.** That is deliberate: if M4–M6 slipped
entirely, M3 still catches the motivating bug and reports it to the right team.

## M4 — Reporting agent (LangGraph)

- `agents/llm.py`, prompts, `agents/schemas.py`, `CostAndEgressCallback`.
- The reporting graph: classify → group → route → narrate.
- `evidence/redact.py` as a graph node; `LLM_EGRESS_LOG`.
- Fallback paths for every LLM node.

**Exit criteria**
- The seeded SCD overwrite is classified `SCD_DEGRADED_TO_OVERWRITE` with cited evidence ids,
  including the commit that caused it.
- With the API key removed, the run still completes and reports with `UNCLASSIFIED`.
- No `LLM_EGRESS_LOG` row shows unredacted PII.
- Thirty related failures group into ≤ 3 incidents.

---

## M5 — Lane B parity (RDS ↔ Snowflake) — the L1 hop

- `parity/canonical.py`, `tier0_aggregate.py`, `tier1_bucket.py`, `tier2_land.py`, `diff.py`,
  `budget.py`.
- `transforms.yaml` support and expiry detection.
- `POST /projects/{p}/parity`, the Parity screen with SSE progress and abort, and the GitHub App
  webhook for the PR gate.

**Exit criteria**
- Identical data: PASS at tier 0, asserted query count, cost well under budget.
- Three divergent rows: tier 2 names those rows and the causing column.
- `layer/duplicate_profile_preserved` confirms bronze kept the source's duplicate multiplicity —
  the check that keeps L2's dedup checks meaningful.
- Budget overrun returns `PARTIAL` with named suspect ranges, never a truncated green.
- The PR gate comments on a real PR and asks the author to declare intent.
- An expensive run can be watched and aborted from the Parity screen mid-tier.
- Scratch tables are always dropped; the sweeper finds nothing.

## M6 — Authoring agent (LangGraph)

- The authoring graph, including the `interrupt()` for grain confirmation and `SnowflakeSaver`
  checkpointing over `DPHM_STATE.GRAPH_CHECKPOINTS` — never a container-local SQLite file, or the
  restart exit criterion below cannot be met (`09` §1.3).
- The layer-contract nodes: `infer_layer_map`, `infer_dedup_contract`, `classify_losses`,
  `infer_measure_map` — producing `layers.yaml` for human confirmation.
- The **Review Queue** screen and `REVIEW_ITEMS`: proposals with their evidence, answered by a
  Data Owner, resuming the checkpointed graph.
- `repo/sql_parse.py` grain candidates, lineage, ownership.
- `open_pr` node; the golden PR test.
- `check repair` loop, capped at two attempts.

**Exit criteria**
- The onboarding wizard on a second, previously unseen dimension produces a PR with a manifest, a
  `layers.yaml` covering all three hops, and a generated SCD suite, all gates green.
- The agent's inferred dedup contract for the M2B hop **matches the one written by hand** in M2B.
  That comparison is the honest test of whether the agent can be trusted to author these.
- A hop whose dedup contract could not be established is emitted as `unvalidated` with zero
  checks and a coverage row — never as a check that would pass by default.
- The run pauses at the Review Queue and resumes correctly **after a service restart** — the
  checkpoint is in `DPHM_STATE`, not on a container's disk.
- A Data Owner can confirm a dedup contract without opening a terminal, and
  `grain_confirmed_by` records their SSO identity.
- With the LLM stubbed out, the graph still completes in degraded mode and says so in the PR body.
- **Onboarding the second project costs ≤ 25% of the first** — the success metric, measured.

---

## M7 — Shadow period and go-live

- Two weeks of shadow running on the real pipeline.
- Weekly report: incident volume, precision from `FEEDBACK`, undeclared differences found (B4).
- Tune tolerances and column rules from what shadow surfaces.
- Go-live is a PR flipping `go_live: true`, approved by the owning team.

**Exit criteria**
- Lane A alerts < 5 per engineer per week.
- Precision > 70% by `FEEDBACK`.
- Mutation-test pass rate 100%.
- A named owner has acknowledged at least one real incident (the C1 / R8 test — the one risk the
  design doc admits is not handled structurally).

## Sequencing rationale

1. **M2 and M2B before any AI.** The gates, the SCD suite, and the dedup contract are the trust
   foundation. Generating checks we cannot validate would be building the amplifier before the
   signal — and writing one layer contract by hand is what makes the agent's inferred contracts
   reviewable in M6.
2. **M3 before M4.** Deterministic reporting proves people act on alerts (C1/R8) before we spend
   effort making those alerts eloquent. An unread alert does not get better by being better
   written.
3. **M5 after M3.** Lane B is the expensive, cross-engine, assumption-violating part. It should
   not be on the critical path to the product's core value.
4. **M6 last.** The authoring agent's job is to make onboarding cheap. That only matters once
   there is a second project, and it is the milestone that most benefits from having seen a real
   manifest built by hand.

## What could reorder this

- If the migration cutover date is near, **M5 moves ahead of M4** — parity is what a cutover
  needs, and an eloquent incident narrative is not.
- If the pipeline repo cannot take a PR check (C2 false), the M5 PR gate drops out and Lane B
  becomes on-demand-only from the app. That is a real capability loss — we stop capturing intent
  at the moment the author still remembers it — and it should be argued for, not absorbed silently.
- If SSO cannot be provisioned in time (Q21), M1 ships behind the ingress's own auth and the RBAC
  roles collapse to one. **Sign-off cannot go live in that state**, because attribution is the
  whole point of a sign-off.
